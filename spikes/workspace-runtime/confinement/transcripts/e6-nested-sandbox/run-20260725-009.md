## What this experiment means

Exactly one OS sandbox means:

```text
Chive harness -> nono Seatbelt sandbox -> coding agent -> shell command
```

It does not mean that every runtime safety option is disabled. Permission
prompts, safe mode, plugin loading, and project worktrees are different from an
OS sandbox:

- a permission rule decides whether the agent may ask to run a tool;
- an OS sandbox limits what the process can reach after the tool starts.

## Claude Code 2.1.218

Claude Code has an optional OS sandbox for Bash commands. On macOS it uses
Seatbelt. The installed user settings have no `sandbox` value, so the feature
is off by default. The current behavior is also described in the
[Claude Code sandbox documentation](https://code.claude.com/docs/en/sandboxing)
and its [settings reference](https://code.claude.com/docs/en/settings).

The test used explicit one-run settings so the result does not depend on a
future user or project setting:

```json
{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false
  }
}
```

The selected outer-only file changed only `enabled`:

```json
{
  "sandbox": {
    "enabled": false
  }
}
```

These files were session artifacts and were removed during cleanup.

`--dangerously-skip-permissions` removes Claude's tool approval prompts because
nono supplies the OS boundary. `--safe-mode` disables custom instructions,
plugins, hooks, and MCP servers for the test. Neither flag turns Claude's Bash
sandbox on or off; the explicit `sandbox.enabled` setting does that.

## OpenCode 1.18.4

The installed OpenCode package and the local source clone both report 1.18.4.
The inspected clone was commit
`62e4641235d7847dadc60da37cca8a023dd54fc1`.

The current command help has no OS-sandbox option. Source inspection found:

- `packages/opencode/src/cli/cmd/run.ts:242` describes `--auto` as automatic
  approval for permissions that are not denied;
- `packages/opencode/src/tool/shell.ts:293` builds a normal child process with
  a working directory and environment;
- `packages/opencode/src/tool/shell.ts:484` starts that child process.

The other word `sandbox` in this source tree refers to project worktrees. It is
not Seatbelt around shell commands. `--pure` disables external plugins, while
`--auto` handles tool approval. Neither creates an OS sandbox.

Command:

```sh
"$HARNESS" --nono "$NONO" \
  --profile opencode-0723a \
  --workspace-rw "$WORKSPACE" \
  --net agent-only \
  --allow-domain api.githubcopilot.com -- \
  /Users/chifeng/.bun/bin/opencode run \
    --format json --pure --auto \
    --dir "$WORKSPACE" \
    --model github-copilot/gpt-5.6-terra \
    'Use the shell tool once to run /bin/pwd. Reply with exactly the printed path.'
```

Result: exit 0. OpenCode's shell tool ran `/bin/pwd`, returned the session
workspace, and OpenCode replied with that exact path. Nono remained active and
recorded denied path and write attempts.

Nono audit session: `0be6a696403737da`.

OpenCode result: no inner OS sandbox needs to be disabled in 1.18.4. Keep
`--pure` and `--auto` only for their plugin and permission meanings, and
recheck this conclusion when OpenCode changes version.
