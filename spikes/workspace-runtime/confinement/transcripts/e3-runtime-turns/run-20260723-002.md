### Root-cause investigation

Initial evidence:

```sh
cd "$WORKSPACE"
git rev-parse --show-toplevel
```

Before the next attempt, this returned `$CHIVE_ROOT`. The first hypothesis was
that OpenCode selected the enclosing Git repository as its tool directory.

### Attempt 002 — Git-boundary hypothesis rejected

The experiment created a session-only empty Git repository inside
`$WORKSPACE`. `git rev-parse --show-toplevel` then returned `$WORKSPACE`. The
exact attempt-001 OpenCode command was repeated with no runtime-argument or
profile change.

Result: **FAIL with the same mismatch.** OpenCode again ran `/bin/pwd` from
`$CHIVE_ROOT`, replied with that path, and exited 0. A local Git boundary does
not control the directory used by this OpenCode tool instance.

### Confirmed cause — stale `PWD`

The exact cause was found later in the OpenCode 1.18.4 source. Nono changes the
real process current directory, but it does not replace the inherited `PWD`
environment variable. OpenCode's `run` handler prefers `process.env.PWD` over
`process.cwd()`, then sends that value to its internal server as the active
directory. Its Bash tool starts in that active directory.

A blocked-network boundary check used the same harness, profile, and workspace:

```sh
"$HARNESS" \
  --nono "$NONO" \
  --profile opencode-0723a \
  --workspace-rw "$WORKSPACE" \
  --net blocked \
  --allow-unix-socket /var/run/mDNSResponder \
  --allow-unix-socket /private/var/run/mDNSResponder \
  -- /Users/chifeng/.local/share/mise/installs/bun/latest/bin/bun -e \
    'console.log("env_PWD=" + process.env.PWD); console.log("real_cwd=" + process.cwd())'
```

It printed:

```text
env_PWD=$CHIVE_ROOT
real_cwd=$WORKSPACE
```

This explains the two OpenCode instances seen in attempt 001. The command
wrapper first loaded an instance from the real cwd, `$WORKSPACE`. The `run`
handler then selected stale `PWD=$CHIVE_ROOT` for its SDK requests, so the
internal server loaded the tool instance rooted at `$CHIVE_ROOT`.

The checked-out `v1.18.4` tag is commit
`49c69c5ed3ccf706b61b3febb43c8aaff7f8325e`. The relevant source is
`packages/opencode/src/cli/cmd/run.ts`: `root` prefers `PWD`, no `--dir`
returns that root, and `--dir` calls `process.chdir` before returning the real
cwd. `opencode run --help` documents `--dir <directory>`.

Attempt 003 adds only OpenCode's supported `--dir "$WORKSPACE"` argument while
keeping the session-only Git boundary, selected profile, nono arguments, model
access, and prompt unchanged.
