## Status

runtime has one working posture through its selected profile: direct access to

E5 asks how each coding agent gets its login credentials while running inside
nono. It compares:

1. direct access to the agent's normal saved login state;
2. nono credential injection, where nono holds a separate API credential and
   adds it to an outgoing request without exposing the real value to the
   sandboxed process.

No credential value is printed or saved in this report.

support groups except `claude_code_macos`, and denies Claude's normal state and
Keychain files. None of the controls replace or edit real login files.

## OpenCode — complete

The selected `opencode-0723a` profile grants read-write access to
`$HOME/.local/share/opencode`, which contains `auth.json`. That one file holds
records for several configured providers. The profile also grants read access
to the login Keychain file with a protection bypass.

The existing-login case used:

```sh
OPENCODE=/Users/chifeng/.bun/bin/opencode

"$HARNESS" --nono /opt/homebrew/bin/nono \
  --profile opencode-0723a \
  --workspace-rw "$WORKSPACE" \
  --net agent-only \
  --allow-domain api.githubcopilot.com -- \
  "$OPENCODE" run \
    --format json --pure --auto \
    --dir "$WORKSPACE" \
    'Reply with exactly OK'
```

Result: exit 0 and reply `OK`. The response used GitHub Copilot. Opaque
provider metadata was not saved.

The first saved-login-denied attempt did not pin a provider. Once `auth.json`
was denied, OpenCode changed to OpenCode Zen, and E4's GitHub-Copilot-only
allowlist denied `opencode.ai`. Session `446186365014b642` is preserved but
does not count because provider fallback confused the result.

The corrected case added:

```sh
--model github-copilot/gpt-5.6-terra
```

With `opencode-no-direct.run-20260725-008.json`, the corrected command exited
1. Seatbelt denied the read of `$HOME/.local/share/opencode/auth.json`, and the
explicit GitHub Copilot turn did not start.

The injection case added `--credential github`. Nono reported
`credential_not_found` because `GITHUB_TOKEN` was absent. More importantly,
the built-in `github` route targets `api.github.com`; it does not supply
OpenCode's GitHub Copilot credential for `api.githubcopilot.com`. The command
still tried `auth.json` and exited 1.

OpenCode result:

- direct existing-login access: **works**;
- nono injection for the current GitHub Copilot setup: **does not work**;
- selected posture: direct access to OpenCode's saved provider records;
- exposure: OpenCode receives read-write access to a state directory holding
