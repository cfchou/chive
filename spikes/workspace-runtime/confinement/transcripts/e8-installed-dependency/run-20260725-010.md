# E8 installed nono dependency and adapter — run-20260725-010

## Result

**PASS for the installed stack and processes that stayed in the adapter
group.** Chive can use the tested user-installed nono 0.69.0 stack. The
installed executable, normal config, selected profiles, input hashes, stdio,
exit codes, and group-targeted cancellation behaved as tested.

A later hostile check found an important limit: a process can call `setsid()`,

unresolved.

The architecture result is **GO**, not “ready to ship.” #32 still needs the
production settings, checks, process-group stop code, and user-facing profile
review described below.

## What Chive owns

```text
Chive backend
  saves one absolute nono path
  checks version, preflight, profile source, and hashes
  starts one adapter-owned process group
  stops that whole group on cancel or force-stop
        |
        v
installed nono + normal config + selected profile
        |
        v
coding agent and commands that stay in the group
```

Chive must stop the process **group**, not only the adapter PID. A process
killed with `SIGKILL` cannot run cleanup code. Sending TERM or KILL to the
adapter-owned group stops the recorded processes that remain in that group. It
does not stop a process that creates a new session or process group.

## 4. Launch without registry access

Attempt 001 used the installed Codex pack with an unreachable registry URL and
disabled update checks:

```sh
NONO_REGISTRY=http://127.0.0.1:1 \
NONO_NO_UPDATE_CHECK=1 \
spikes/workspace-runtime/confinement/sidecar-harness/target/debug/sidecar-harness \
  --nono /opt/homebrew/Cellar/nono/0.69.0/bin/nono \
  --profile nolabs-ai/codex \
  --workspace-rw tmp/confinement-runs/run-20260725-010/workspace \
  --net open \
  -- /bin/true
```

Nono verified the installed pack locally, then rejected `/bin/true` because
that command is not allowed by the selected profile. This was a command-policy
failure, not a registry failure.

Attempt 002 repeated the same command with `/bin/pwd`, which the selected
profile permits. It printed the session workspace and exited 0. No pull,
update, wiring, promotion, or normal-config write ran. Nono 0.69.0 source also
disables its background update check for `run`, `shell`, and `wrap` commands.
Chive should still set `NONO_NO_UPDATE_CHECK=1` for runtime launches so this
rule is explicit.

## 6. Cancellation of processes that stay in the group

The first test was intentionally run before the fix:

```sh
spikes/workspace-runtime/confinement/sidecar-harness/scripts/run-process-cleanup.sh \
  spikes/workspace-runtime/confinement/sidecar-harness/target/debug/sidecar-harness \
  /opt/homebrew/bin/nono \
  default \
  tmp/confinement-runs/run-20260725-010/workspace
```

Red result:

```text
RESULT signal=TERM cleanup=fail owner-group=missing
RESULT signal=KILL cleanup=fail owner-group=missing
SUMMARY cleanup-failures=2
```

The smallest fix makes the adapter its own Unix process-group leader before it
starts nono. Nono, the runtime shell, and ordinary later grandchildren inherit
that group. The caller can then stop that recorded group without matching
processes by command name.

Rust checks, run against this Cargo project:

```sh
cargo test \
  --manifest-path spikes/workspace-runtime/confinement/sidecar-harness/Cargo.toml
```

Result: 15 tests passed.

The live lifecycle command was then rerun. Green result:

```text
CASE signal=TERM wrapper=97806 group=97806 descendants=97808 97809 97810 97811
RESULT signal=TERM cleanup=pass survivors=none
CASE signal=KILL wrapper=97840 group=97840 descendants=97842 97843 97844 97845
RESULT signal=KILL cleanup=pass survivors=none
SUMMARY cleanup-failures=0
```

TERM covers normal cancellation. KILL covers forced stop. Each case recorded
the adapter, nono, runtime shell, and grandchildren before the stop. No
recorded process survived.

This test did not make a child leave the group. The 2026-07-26 follow-up added
that hostile case and failed, so this green result must not be read as complete
descendant cleanup.

## 7. What the user must see before trusting a profile

The selected effective profiles currently have no profile `hooks`,
`session_hooks`, `command_args`, or `unsafe_macos_seatbelt_rules`. Installed
packs do contain separate setup/wiring files; Chive must show them as pack
metadata and must never run wiring during an ordinary runtime launch.

The selected profiles are compatibility defaults, not exact-workspace
profiles:

- all three inherit broad macOS reads such as `/Volumes` and `/Applications`;
- Codex can read and write its full normal state directories;
- Claude can read and write the whole login Keychain directory and bypasses
  nono's normal Keychain deny;
- OpenCode can read its multi-provider state and the login Keychain file;
- Chive passes the runtime executable, its full arguments, the workspace, the
  final allowed domains, and requested credential routes at launch.

The profile source, broad access, hooks, unsafe rules, command arguments, and
credential posture must be visible before the user accepts a profile. Chive
must not call these selected profiles exact-workspace confinement.

## 9. License and distribution

Nono 0.69.0 is Apache-2.0. Chive does not copy, bundle, or redistribute the
nono executable, packs, or profiles in this design, so this is an external
program dependency rather than bundled third-party code. Product docs should
name the supported nono version, link to upstream and its Apache-2.0 license,
and explain that the user manages the installation. If Chive later bundles
nono, the distribution decision must be reopened and the Apache license and
any upstream NOTICE file must be shipped as required.

The external CLI does not raise Chive's Rust toolchain floor.
