# E8 detached-process cleanup follow-up — run-20260726-011

## Result

**FAIL.** Sending TERM to the adapter's process group did not stop a helper
that called `setsid()` and double-forked. The final daemon moved into another
process group and remained alive until the test cleaned up its exact recorded
PID.

This does not reject the installed-nono architecture. It proves that the
current process-group stop is incomplete. Chive must not promise that it stops
every command an agent starts until #32 adds and tests a stronger lifecycle
boundary.

```text
adapter group --TERM--> stopped

detached daemon
  called setsid()
  moved to another group
  survived the adapter-group signal
```

## What remains open

The adapter can reliably signal processes that stay in its process group. It
cannot stop a process that deliberately creates another session or process
group. Complete detached-process cleanup remains production work for #32.
